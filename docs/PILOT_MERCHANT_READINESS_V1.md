# PHOENIX Pilot Merchant Readiness V1

## Objective

Prepare one truthful pilot merchant/operator workflow for the Live Selling Operations wedge without implying production capability or crossing PHOENIX runner, production, DNS, credential, payment, or repository-trust boundaries.

## Pilot operating loop

The pilot proof follows:

**Plan → Create → Go Live → Sell → Measure → Improve**

Each stage must use actual PHOENIX product evidence when implemented. Prototype, preview, concept, and planned states must remain visibly distinct from verified live capability.

## Admission gate

A pilot is ready for operator rehearsal only when:

- the merchant/operator scenario is defined without inventing a customer or partnership;
- required inputs and accountable operator are identified;
- the product path can be exercised deterministically in the approved non-production environment;
- no real payment or production commerce dependency is required for the rehearsal;
- expected evidence is defined before execution;
- rollback/reset instructions exist for mutable test data.

## Evidence contract

For each stage capture only evidence that actually exists:

1. **Plan** — session objective, products/sample data source, operator checklist.
2. **Create** — approved content/assets or clearly labeled demo assets.
3. **Go Live** — session-state UI or truthful prototype/preview evidence.
4. **Sell** — attributable commerce flow using non-production/demo data unless real commerce is separately authorized.
5. **Measure** — actual captured events/metrics only; never invented GMV, orders, viewers, ROAS, profit, or conversion.
6. **Improve** — evidence-backed action or experiment derived from the measured result.

## Visual-first proof

Use actual product screens first. Every screenshot/demo must show its capability state where ambiguity is possible:

- **LIVE PRODUCT** — verified working capability in its stated environment.
- **PROTOTYPE / PREVIEW** — implemented demonstration that is not production proof.
- **CONCEPT / PLANNED** — explanatory direction only.

Do not fabricate merchants, creators, viewers, orders, revenue, testimonials, integrations, attribution, or profitability.

## Pilot readiness result

A rehearsal may be marked **READY** only when the full non-production path is repeatable and the evidence package identifies:

- exact commit/release identity;
- environment;
- deterministic test result;
- operator steps;
- known limitations;
- recovery/reset procedure.

Otherwise record **NOT READY** and the exact blocker.

## Stop / escalation boundaries

Stop before:

- registering or attaching a self-hosted runner;
- changing repository visibility;
- using runner-registration tokens or unrelated project credentials;
- production deployment or host bootstrap;
- DNS/Cloudflare changes;
- exposing databases or secrets;
- accepting/spending money;
- publishing or sending externally;
- claiming a real pilot merchant, partnership, result, sale, order, or metric without evidence.

These boundaries do not block repository-only implementation, deterministic tests, documentation, truthful demo preparation, or pilot operating design.
